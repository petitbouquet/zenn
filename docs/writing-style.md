# 書き方の決まり —— AI が書いた感じを抜く

**Jev の記事の下書きに対して、本人からもらった指摘の記録**（2026-09-20、2回に分けて）。
次に記事を書くときは、書き始める前にここを読む。

---

## ★ 0. 感想を勝手に代弁しない ★

**いちばん大事。**

下書きの最後を「**しばらく使ってみます。**」で締めていた。これは**使うかどうかを本人が決める話**で、書き手が勝手に決めていい感想ではない。

> **使うかどうか決めるのは私です。感想を勝手に代弁せず、次からはインタビューをしてほしいかな。**

### どうするか

**感想・評価・今後の予定が要るところに来たら、書かずに聞く。**

| 勝手に書いてはいけないもの | 例 |
| --- | --- |
| **これから何をするか** | 「しばらく使ってみます」「次は◯◯を試します」 |
| **好き嫌い・評価** | 「気に入りました」「物足りませんでした」 |
| **本人の状況** | 「業務でも使えそうです」 |

★ **事実は書いていい。感想は聞く。** ★
「300ms で返ってきました」は事実。「速くて気持ちいいです」は感想。

## 1. 論述っぽさが強い

> メリットデメリットの評価に終始し、感想が含まれないため無機質な AI らしさを感じる

**口語体で書く。** やわらかさの基準は [/about](https://poina.petit-bouquet.com/about) と同じくらい。

- **です・ます**で書く
- **1文を短く**
- 「〜してくれます」「〜みたくて作りました」のような、人の動きが見える言い方にする

### ★ 本人の語彙に寄せる ★

| よく使う言葉 | |
| --- | --- |
| **うれしい / たのしい / たすかる / すばらしい** | ここに寄せる |

| 使わない | なぜ | 言い換え |
| --- | --- | --- |
| **うまみ** | ビジネス的な強調 | いちばん役に立つ手段です |
| **面倒を見る** | 同上 | 気にしなくていい |
| **痛い** | 同上 | 直すのが大変 |
| **神** | ★ **セールス調。ダサい** ★ | （書かない） |

**例:**

| 前 | いま |
| --- | --- |
| やりたいことが「分類」の形になっていないと、うまみが出ません | やりたいことが「分類」なら、いちばん役に立つ手段だと思います |
| あれの面倒を見なくていいのは、楽でした | あれを気にしなくていいのは、たすかりました |
| 画面を全部作ったあとで気づくと痛い | 画面を全部作ったあとで気づくと直すのが大変 |

## 2. ★ エージェント癖を出さない ★

> 「見ておきました」などの「おきました」
> 業務報告でレビュワーがいる想定なのが違和感。ブログなので自己完結

**「〜しておきました」「〜しておきます」は、報告する相手がいる書き方。**
ブログに読み手はいても、**承認する人はいない。**

| 使わない | 言い換え |
| --- | --- |
| 確率の出かたを見ておきました | 確率の出かたを**チェック** |
| 先に見ておいてよかったです | 先に**チェックして**よかったです |
| 1つだけ共有しておきます | 1つだけ共有します |

### 見出しにセールス調を持ち込まない

| 前 | いま |
| --- | --- |
| 1 回 0.02 円は、さすがに神 | **費用感もチェック** |

**数字を煽り文句にしない。** 数字は本文で出せば伝わる。

## 3. 長い

> 詳細で確実な説明を望む読者は少ないです。

**下書きは本文だけで 15,600 字あった。** いまは 7,500 字くらい。

### 最初に要点を 3 行

**タイトルのすぐ下に、3 行で「何の話か」を置く。**

### 伝えたいことを先に決めて、そこから外れたものは落とす

Jev の記事のときに決めたのはこの 7 つ。

1. Cloudflare で Jev を実際に運用した
2. 16 タイプ診断は、16 択の判断をする題材としてちょうどよかった
3. 1 診断ぶんのトークンでほぼ費用がかからない
4. Claude Code で日曜日の午前中に実装が終わった
5. 曖昧な要求に答える条件分岐として使えそう
6. **精度は未検証。受けてみて合っていたか X で教えてほしい**
7. リーガル面のケア

> ★ **章を足したくなったら、この一覧のどれに当たるかを言えるか確かめる。** ★

### ★ 読者の疑問に答える。仔細を説明しない ★

**権利の話を3つの節に分けて 1,500 字書いていた。説明しすぎ。**

> 読者が知りたいのは、権利の状況の仔細ではなく
> 「この手の診断サイトを作って、権利に違反していないの？」という疑問に対する
> **安心できるアンサー**です。

→ **2〜3 文で足りる。**

```
MBTI は Myers & Briggs Foundation の商標で、日本でも教育・娯楽の区分で
登録されています。なのでこのサイトはその名前を名乗っていませんし、16タイプの
呼び名も説明文も設問30問も、ぜんぶ自分たちで書きました。借りているのは
「4つの指標を組み合わせる」という考え方だけで、そこはアイデアなので誰でも使えます。
```

**調べた過程はリポジトリの `docs/legal-check.md` に置いてある。** 記事に全部出さない。

## 4. AI っぽい言葉を使わない

> AI 特有の、断言ワードや、英語直訳ワード（静かに、直ちに、正本、効く、投げきる、だいたい）は
> 別の言い換えをしてほしい

| 使わない | 言い換え |
| --- | --- |
| 静かに（〜する） | そっと / 黙って / とくに何も言わずに |
| 直ちに | すぐに |
| 正本 | 元の場所 / ここが本物 |
| 効く | 役に立つ / ここがうれしい |
| 投げきる | 1 回で送れる / まとめて渡せる |
| だいたい | たいてい / ほとんど / ざっくり |
| 形が崩れない | ★ **出力の型が決まっている** ★（あいまいで逆に分かりにくい） |

**下書きで自分が使っていて、直したもの:**

| 使わない | なぜ |
| --- | --- |
| 〜が要点だ / 〜が本題 | **記事の構造を説明しているだけ**。読者には関係ない |
| 裏を返すと | 翻訳調。「逆に言うと」にする |
| 〜に他ならない / 明らかに | 断言が強すぎる |
| 実質ゼロだが、無料ではない | ★ **対句で締めるクセ** ★ 続くと型にはめて書いているように見える |

### 為替を書かない

**「0.02 円」と書くと、時間が経ってから読んだ人には嘘になる。**
ドルで書くか、「1万回やっても 2 ドルいきません」のように**規模で伝える。**
