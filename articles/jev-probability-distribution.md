## Jev って何？

2026年9月に TypeSafe AI が出した、**文章を書かない AI** です。

普通の LLM はテキストを返しますが、Jev は返しません。選択肢を渡すと、**そのどれにどれくらい近いか**を数字で返してくれます。それだけです。

```json
{
  "choice": "INFP",
  "confidence": 0.68,
  "probabilities": { "INFP": 0.70, "INFJ": 0.24, "INTP": 0.03, "...": 0 }
}
```

何がうれしいかというと、**パースに失敗しないところ**です。

LLM に JSON を返してもらうと、たまに ```` ```json ```` が付いてきたり、前置きが混ざったりします。あれを気にしなくていいのは、思っていたよりずっとたすかりました。

## 16タイプ診断が、題材としてちょうどよかった

Jev は「if 文と LLM のあいだを埋める道具」と説明されています。逆に言うと、**やりたいことが「分類」なら、いちばん役に立つ手段**だと思います。

16タイプの性格診断は、そこにぴったりはまりました。

- 選ぶ先が **16個で固定**
- ほしいのは「どれか1つ」じゃなく **「どれにどれくらい近いか」**
- Jev の `choice` は選択肢を 255 個まで取れるので、16個なら 1 回でまとめて渡せます

渡すものはこれだけです。

```ts
await env.AI.run('typesafe/jev', {
  state: {
    回答: [
      { 設問: '知らない人が多い集まりでも、わりと平気で話しかけにいく。', 目盛り: 20 },
      // …
    ],
  },
  questions: {
    type: {
      type: 'choice',
      instructions: 'この回答をした人は、16タイプのうちどれにいちばん近いか。',
      criteria: { INTJ: 'ひとりの時間で元気が戻り…', INTP: '…' }, // 16個
    },
  },
})
```

### 画面を作る前に、確率の出かたをチェック

「2番目・3番目も出したい」という要件があったのですが、**1位に全部持っていかれる出かたしかしないなら、この要件はそもそも成り立ちません。**

画面を全部作ったあとで気づくと直すのが大変なので、先にダミーの回答を投げて確かめました。

| 投げたもの | 1位 | 2位 | 3位 |
| --- | --- | --- | --- |
| はっきり INTJ に寄せた | INTJ 96% | ISTJ 2% | INTP 2% |
| ゆるく INFP に寄せた | INFP 73% | INFJ 18% | INTP 6% |
| 全部まんなか | INTP 51% | ISTJ 19% | INTJ 7% |

はっきり寄せれば尖るし、ゆるく寄せれば散ってくれました。人が実際にやりそうな「ゆるく寄った」回答で 2位 18% なら、参考として出す意味があります。

これを見てから画面を作り始めました。**先にチェックしてよかったです。**

## 費用感もチェック

10問と30問で1回ずつ測りました。

| モード | 入力 | 出力 | 費用 | 応答 |
| --- | --- | --- | --- | --- |
| おためし（10問） | 3,035 | 149（**課金されません**） | $0.000127 | 294ms |
| しっかり（30問） | 4,162 | 149（**課金されません**） | $0.000175 | 283ms |

**1万回やっても 2 ドルいきません。** 出力は文章を返さないぶん、そもそも課金対象になっていません。

### 測り方

Jev のレスポンスに `usage` が入っているので、それをそのまま読んでいます。

```ts
const res = (raw?.result ?? raw) as {
  usage?: { input_tokens: number; output_tokens: number }
}
```

同じ寄せ方のダミー回答を、10問と30問で1回ずつ投げました。AI Gateway を通すとキャッシュが返ってくることがあるので、**手元からゲートウェイを迂回して**測っています。

### 設問を3倍にしても、入力は1.4倍でした

ここは測ってみて「へえ」と思ったところです。

計算してみると、**設問1問で増えるのは56トークンくらい**。残りの**2,472トークンは、問数に関係なく毎回渡している部分**でした。16タイプぶんの判定の手がかりが、そのほとんどを占めています。

つまり **費用のほとんどは「16タイプの説明」のほうで、設問ではありません。** 設問を増やすかどうか迷っていたのですが、費用の面では気にしなくてよさそうです。

この程度のコストで済むなら、**趣味での AI 活用も捗りそう**ですね！

:::message
`wrangler dev` で手元から呼んでも本物の API を叩くので、開発中も少しずつ課金されます。とはいえ何百回試しても数円です。
:::

## 引っかかったところ

1つだけ共有します。**最初、5回続けて 502 になりました。**

```
X [ERROR] judge failed: 判定モデルが確率を返さなかった
[wrangler:info] POST /api/judge 502 Bad Gateway (285ms)
```

生のレスポンスを見て分かったのですが、**Workers AI から呼ぶと、返ってくるものが `result` で包まれます。**

```json
{
  "state": "Completed",
  "result": { "answers": { "type": { "choice": "ENTJ", "probabilities": { } } } }
}
```

TypeSafe の API を直接叩くと包まれないので、サンプルのまま `res.answers` を読みにいくと `undefined` になります。

まいったのは、**モデルのほうは 285ms でちゃんと答えていた**ことです。返事は正しいのに、こちらが読めていないだけ。「変な答えが返ってきているのかな」と思って調べにいくと遠回りします。

両方の形を読めるようにして解決しました。

```ts
const res = (raw?.result ?? raw) as { answers?: { type?: JevChoiceAnswer } }
```

## 権利まわりは大丈夫？

MBTI は Myers & Briggs Foundation の商標で、日本でも教育・娯楽の区分で登録されています。なので**このサイトはその名前を名乗っていません**し、**16タイプの呼び名も説明文も設問30問も、ぜんぶ自分たちで書きました**。借りているのは「4つの指標を組み合わせる」という考え方だけで、そこはアイデアなので誰でも使えます（自分で調べた範囲の話なので、参考程度に読んでください）。

![性格タイプ一覧。自作の愛称と説明文が並んでいる](/images/poina-types.png)
*「先を描くひと」「なぜを掘るひと」みたいな名前も、ぜんぶ考えました*

Jev に渡す判定の手がかり（`criteria`）は、要するに「そのタイプはどういう人か」を書いたもの。つまり**サイトに出す説明文と、モデルに渡すものがほぼ同じ**になりました。説明文を練る作業が、そのまま精度を詰める作業になっていたわけです。
