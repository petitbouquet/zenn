## 頼んだこと

【聞く：ペイントソフトを題材にした理由。クラウドセッションを試そうと思ったきっかけ】

Claude Code に渡したのは、できてほしいことの箇条書きと、「PC の Chrome だけでいい」「wasm で速くしてほしい」の 2 つです。

- レイヤーわけ・統合、乗算レイヤー
- カラーパレット、スポイト
- 参考画像のサブウィンドウ
- 鉛筆、ペン、筆の 3 種類の線と消しゴム
- 範囲選択（塗りつぶし、切り抜き、貼り付け）、バケツ塗りつぶし
- 文字入力、背景色の変更と透過、画像の書き出し
- そのほか、イラストを描く人に必要な機能（調べてほしい）

最後の 1 行について、Claude Code はイラスト向けのペイントソフトの機能一覧と使い方の解説を見比べて、取り消し・筆圧・手ブレ補正・左右反転表示・クリッピング・透明ピクセルのロック・PSD の書き出しなどを足してきました。左右反転は、デッサンの狂いを見つけるときの定番の確かめ方だそうです。

## 任せる前に、手元でやったこと

クラウドセッションは、手元のファイルを見られません。
私は作業の決まりごとを `knowledge/` というディレクトリにまとめていて、ふだんは Claude Code にそれを最初に読ませています。クラウドにはそれが無いので、手元のセッションで先にこれだけやってもらいました。

1. knowledge を読んで、決めることを決める（検索に出すか、計測するか、誰が push するか、文言の声の高さ など）
2. 決めたことと理由を、リポジトリの `CLAUDE.md` に写す
3. 作る順番を 9 段に分けて、各段で版を上げてコミットする、と書く
4. 骨組みだけコミットして、クラウドに移る

私がやったのは、計画を読んで承認したことと、アプリの名前を 3 つの案から選んだことだけです。

1 つだけ、ふだんの決まりを破っています。ふだんは push を私がやっていますが、「承認したらあとは全自動で」とお願いしたので、クラウドにいる間だけは Claude Code が push してよいことにしました。`CLAUDE.md` にはそれを例外として、範囲（クラウドにいる間だけ、本番に出すのは私）と一緒に書いてあります。手元に戻ったあと、記録をそろえるときに Claude Code がこの例外に取り消し線を引いて「終わった」と書き直しました。

## 中の作り

絵の中身は全部 Rust で書いて、wasm にしています。JavaScript が持つのは画面と入力だけです。

- レイヤーは 256×256 のタイルの集まりで、何も描いていないタイルはメモリを使いません
- 取り消しは、操作の前の状態を丸ごと積んでいます。タイルは `Rc` で持っているので、状態を複製しても画素はコピーされません。書き換えるときだけ `Rc::make_mut` で複製されるので、記録に残るのは変わったタイルの前の中身だけです
- 合成は wasm がやり、表示は WebGL2 がやります。変わったタイルだけを GPU に送って、拡大・回転・左右反転は GPU で描いています

4000×4000 に太さ 60 の線を 100 本引いても、取り消しの記録は 94MB でした。

## 速さ

完了条件を数字で決めておいて、v1.0.0 の前に全部測ってもらいました。測ったのはクラウドの環境（Xeon 2.1GHz・4 コア、headless Chromium で WebGL は CPU で描く SwiftShader）です。

| 条件 | 結果 |
| --- | --- |
| 4000×4000・20 レイヤーで、1 フレームが 16ms 以内 | p50 0.30ms、p95 0.50〜0.70ms |
| 4000×4000 のバケツ塗りが 100ms 以内 | 4・5 回目は 61〜64ms。1〜3 回目は 239〜335ms |
| 取り消し 100 回ぶんで 1GB を超えない | 記録 94MB、wasm のメモリ 154〜200MB |

バケツだけは、開いてから最初の数回が条件を超えています。新しいメモリに初めて触るときの重さと見ていて、直さずに「分かっていて残しているもの」として `CLAUDE.md` に書いてあります。

## 手元の Windows で 4 回止まった


クラウドで v1.0.0 になったあと、私の Windows で本番に出そうとしたら、4 回続けて止まりました。クラウドは Linux なので、Windows でしか起きないことは 1 つも見つからなかったんです。

| 版 | 手元で起きたこと | 直し方 |
| --- | --- | --- |
| v1.0.1 | `cargo install wasm-pack` が `linker 'link.exe' not found` で落ちる | Windows の Rust は C++ のビルド道具でつなぐので、Visual Studio Build Tools の C++ を先に入れる |
| v1.0.2 | OGP の画像を焼くところで `headless_shell.exe` が無い | `npm install` では Playwright の本体しか入らない。`npx playwright install chromium` が別に要る |
| v1.0.3 | 点検が `Cannot read properties of undefined` で落ちる | `path.relative()` が Windows では `public\index.html` を返していた。ファイル名を比べる前に `/` にそろえる |
| v1.0.4 | 本番に出すところで `spawnSync npx ENOENT` | Windows の npx は `npx.cmd` で、`execFileSync` はシェル無しでは起動できない。`node_modules/wrangler/bin/wrangler.js` を `process.execPath` で直に動かす |

止まるたびに Claude Code が直して版を上げました。4 つの直しのコミットは、11:48 から 12:00 までの 12 分に並んでいます。

`cargo install wasm-pack` のときは、失敗したあとに `CARGO_BUILD_BUILD_DIR` についてのお知らせが最後に出ます。これが原因に見えるのですが、関係ありません。本当の理由はその上の `link.exe` です。

次に同じ形で作るなら、出す仕組み（子プロセスの起動とパスの扱い）だけ先に手元の Windows で 1 回通してから任せる、と knowledge に書きました。
【聞く：これについて本人の考えがあれば足す】

ほかにも、クラウドならではのことが 2 つありました。

- git のタグの push が、クラウドのプロキシに 403 で断られました。コミットは届いています。タグは、打ち直すコマンドを Claude Code が `CLAUDE.md` に並べておいてくれたので、手元で打ち直しました
- クラウドのセッションに移るとき、アプリが代わりに push しようとして失敗しました。Git Bash の ssh が Windows の ssh-agent を見ないためで、`git -c core.sshCommand=C:/Windows/System32/OpenSSH/ssh.exe push` で先に push してから移りました

## 絵はブラウザから出ていきません

保存は、ブラウザの中（IndexedDB）への自動保存と、パソコンへのファイル保存だけです。サーバのコードはありません。Cloudflare Workers は静的なファイルを配っているだけです。

このアプリについてのページには、この 1 文を足しました。

> 完成した絵はサーバに保存されることはないので、本サイトの権限において検閲やAI学習をすることはありません。
