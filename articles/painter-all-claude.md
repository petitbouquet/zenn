## 作ろうと思ったきっかけ

CLIP STUDIO PAINT の、表現に関する基準の見直しが話題になっているのを見かけました。

https://x.com/clip_celsys/status/2102638460188467677

仔細は知らないのですが、それをきっかけに、Claude で自分用のペイントソフトを作っている絵師さんもいる、という話を耳にしました。
それなら私も作ってみよう、と思ったのがはじまりです。作ったものが実際に使い物になりそうかも確かめたくなりました。

ちょうど Claude Code のクラウドセッションが公開された記念に、Pro ユーザー向けに $100 分のクラウドセッションの無料クレジットが配られていました。せっかくなので、クラウドセッションにどこまで任せられるかもあわせて試しました。

## 頼んだこと

Claude Code に渡したのは、できてほしいことの箇条書きと、「PC の Chrome だけでいい」「wasm で速くしてほしい」の 2 つです。

- レイヤーわけ・統合、乗算レイヤー
- カラーパレット、スポイト
- 参考画像のサブウィンドウ
- 鉛筆、ペン、筆の 3 種類の線と消しゴム
- 範囲選択（塗りつぶし、切り抜き、貼り付け）、バケツ塗りつぶし
- 文字入力、背景色の変更と透過、画像の書き出し
- そのほか、イラストを描く人に必要な機能（調べてほしい）

最後の 1 行について、Claude Code はイラスト向けのペイントソフトの機能一覧と使い方の解説を見比べて、取り消し・筆圧・手ブレ補正・左右反転表示・クリッピング・透明ピクセルのロック・PSD の書き出しなどを足してきました。左右反転は、デッサンの狂いを見つけるときの定番の確かめ方だそうです。

## 任せる前に、手元でやったこと

クラウドセッションは、手元のファイルを見られません。
私は作業の決まりごとを `knowledge/` というディレクトリにまとめていて、ふだんは Claude Code にそれを最初に読ませています。クラウドにはそれが無いので、手元のセッションで先にこれだけやってもらいました。

1. knowledge を読んで、決めることを決める（検索に出すか、計測するか、誰が push するか、文言の声の高さ など）
2. 決めたことと理由を、リポジトリの `CLAUDE.md` に写す
3. 作る順番を 9 段に分けて、各段で版を上げてコミットする、と書く
4. 骨組みだけコミットして、クラウドに移る

私がやったのは、計画を読んで承認したことと、アプリの名前を 3 つの案から選んだことだけです。

1 つだけ、ふだんの決まりを破っています。ふだんは push を私がやっていますが、「承認したらあとは全自動で」とお願いしたので、クラウドにいる間だけは Claude Code が push してよいことにしました。`CLAUDE.md` にはそれを例外として、範囲（クラウドにいる間だけ、本番に出すのは私）と一緒に書いてあります。手元に戻ったあと、記録をそろえるときに Claude Code がこの例外に取り消し線を引いて「終わった」と書き直しました。

この 2 時間、私は動画を見たり、トリッカルの日課をこなしたりしながら、ときどき様子を見ていました。

## 手元の Windows で 4 回止まった

クラウドで v1.0.0 になったあと、私の Windows で本番に出そうとしたら 4 回止まりました。C++ のビルド道具（`link.exe`）が無い、Playwright の Chromium が入っていない、パスの区切りが `\` になる、`npx` が `npx.cmd` で起動できない、の 4 つです。どれもクラウド（Linux）では起きないものでした。
止まるたびに Claude Code が直して版を上げて、4 つの直しは 12 分で済みました。

## できあがったものの評価

wasm を選んだのは、画像を扱う込み入ったアプリなので、機能の多さと速さを両立したかったからです。
絵の中身（256×256 のタイルに分けたレイヤー、ブラシ、合成、バケツ、取り消し）は全部 Rust で書いて wasm にしてあり、JavaScript は画面と入力、WebGL2 は表示だけを受け持っています。保存もブラウザの中だけで、サーバのコードはありません。

速さは完了条件を数字で決めておいて、v1.0.0 の前に測ってもらいました。測ったのはクラウドの環境（Xeon 2.1GHz・4 コア、WebGL を CPU で描く headless Chromium）です。

| 条件 | 結果 |
| --- | --- |
| 4000×4000・20 レイヤーで、1 フレームが 16ms 以内 | p95 0.50〜0.70ms |
| 4000×4000 のバケツ塗りが 100ms 以内 | 4 回目からは 61〜64ms（最初の 3 回は 239〜335ms） |
| 取り消し 100 回ぶんで 1GB を超えない | 記録 94MB |

バケツの最初の数回だけは条件を超えていて、「分かっていて残しているもの」として `CLAUDE.md` に書いてあります。

私は絵師ではないので、ペンタブで筆圧や描き味をじっくり確かめるところまではできていません。マウスで描いてみた範囲では、手ブレ補正が効いているのが体感できるくらいで、印象はよかったです。絵を描く人にとって本当に使いやすいかどうかまでは、まだ分かっていません。

使ったのは、クラウドセッションの無料クレジットのうち $32 です。$32 でこのクオリティのものが作れるなら大満足です。

## 追記：スマホとタブレットでも描けるようにした

記事を出したあと、スマホとタブレットにも対応しました。iPad と Apple Pencil で描けることを必須にして、もう一度クラウドセッションにまかせています。

要件を書いてから対応がひととおりそろうまで（v1.8.0〜v1.11.1）、約 45 分でした。入れたのはこのあたりです。

- スマホでは、キャンバスを画面いっぱいにして、道具は紙の外をたたくと下から出るシートに入れる
- タブレットでは周りを一回り小さくして、縦向きのときは色とレイヤーのパネルを引き出しにする
- 指 2 本でつまんで拡大・回転、2 本指のタップで取り消し、3 本指のタップでやり直し
- フルスクリーンのモードと、ホーム画面への追加

クラウドには iPad のブラウザ（WebKit）が無いので、テストは Chromium でスマホやタブレットのふりをして動かしています。テストは全部通っていましたが、私の iPad とスマホで触ってみると 5 つ引っかかりました。

- キャンバスの上に浮かべたボタンと太さのスライダーが、指でたたいても効かない
- タブレットの上のメニューで、隣をたたくと開いてすぐ閉じる
- 作品ファイル（.pnh）が、ファイルを選ぶ画面で選べない
- 道具の列をすばやく 2 回たたくと、ページが拡大・縮小する
- 縦長の画面でも、はじめの紙が横長

1 つ目は、iPad のダブルタップでの拡大を止めるために、キャンバスの入れ物で `touchstart` を止めていたのが原因でした。その上に載せたボタンやスライダーまで一緒に止まっていました。
テストはボタンをマウスの形で押していたので、指で触ったときの `touchstart` が出ず、気づけませんでした。指で押すテストに変えて、直す前に落ちるのを確かめてから直しています。
5 つとも手元のセッションで直して、ここで一区切りにして v2.0.0 にしました。

Apple Pencil の筆圧は正しく認識できていたので、良いと思います。

モバイル対応で使ったクレジットは $28 で、最初の $32 と合わせて $60 です。
